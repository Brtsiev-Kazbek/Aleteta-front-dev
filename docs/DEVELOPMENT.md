# Руководство разработчика

Как поднять проект, как он устроен и по каким правилам в нём пишут. Документ
рассчитан на человека, который открыл репозиторий впервые и хочет через час
внести осмысленную правку.

---

## 1. Запуск за пять минут

```bash
npm install
cp .env.example .env.local     # заполнить адрес проекта и ключи Supabase
npm run dev                    # http://localhost:3000
```

Без `.env.local` приложение всё равно откроется — оно работает на встроенном
наборе данных. Это не аварийный режим, а поддерживаемый: лендинг и продуктовые
экраны можно смотреть на свежем клоне, ничего не настраивая.

С базой порядок такой:

```bash
npx supabase login
npm run db:link -- <project-ref>   # часть адреса: https://<project-ref>.supabase.co
npm run db:push                    # применить миграции
npm run db:seed                    # демонстрационные дела (по желанию)
npm run db:types                   # перегенерировать types/database.ts
```

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Разработка с горячей перезагрузкой |
| `npm run build` | Боевая сборка. Гоняйте перед каждым коммитом |
| `npm run typecheck` | Проверка типов без сборки |
| `npm run lint` | ESLint по правилам Next |
| `npm run docs:api` | Пересобрать справочник в `docs/api` |
| `npm run db:diff` | Показать расхождение схемы с миграциями |

## 3. Как здесь пишут

### Комментарии объясняют «почему», а не «что»

`// увеличиваем счётчик` — мусор, это видно из кода. Полезный комментарий
отвечает на вопрос, который возникнет у того, кто захочет «упростить»:

```ts
/*
 * SECURITY DEFINER здесь обязателен, а не для удобства: политика на
 * workspace_members не может сама читать workspace_members — Postgres уйдёт
 * в бесконечную рекурсию.
 */
```

Такой комментарий экономит час раскопок и предотвращает поломку.

### Запись в базу — только через серверные действия

Клиентский код никогда не пишет в базу напрямую. Причины две: `workspace_id`
нельзя принимать от клиента (иначе запись можно приписать к чужому
пространству), и проверки, живущие только в браузере, обходит любой прямой
запрос.

Действие возвращает значение, а не бросает исключение:

```ts
export async function updateCaseAction(...): Promise<ActionResult<Case>> {
  if (!title.trim()) return actionFail("Название дела не может быть пустым.");
  ...
}
```

Исключение через границу «сервер → клиент» в боевой сборке приходит
обезличенным — React прячет текст, чтобы наружу не утекли внутренности.
Поэтому ожидаемый отказ возвращается значением и доезжает до формы читаемым.

### Правка применяется сразу, запись идёт следом

Таблица реквизитов не должна замирать на круг до сервера. Поэтому изменение
кладётся в стор немедленно, а `sync()` пишет его в базу и откатывает, если
база отказала. Отказ показывается плашкой `SyncStatus` — молча терять правку
нельзя.

Смотреть: `store/sync.ts`, функция `createSync`.

### Стор разложен по слоям, и один из них настоящий

`store/slices/` — восемь файлов по предметам: дела, объекты, документы,
распознавание, оболочка, ассистент, генерация, разбор. Собираются они в
`useAppStore`, и для компонентов ничего не изменилось: это по-прежнему один
объект с теми же полями.

Разделение было нужно не ради размера файла, а ради одной границы. Три слоя из
восьми — **имитация**: прогресс двигает `setInterval`, ответы взяты из
заготовок, документы создаются с пустой ссылкой. Пока всё это лежало вперемешку
с настоящим кодом, отличить работающее от нарисованного можно было только
чтением построчно.

Теперь граница видна по импорту: всё, что тянет `store/demo.ts`, — имитация.
Настоящее сейчас одно — `slices/recognition.ts`, и по нему видно, чем настоящая
операция отличается от изображённой:

- она **продолжается, когда вкладка закрыта**, поэтому есть возобновление
  наблюдения после перезагрузки;
- она **может не получиться**, поэтому у ошибки есть место, где её видно, и
  повтор по нажатию;
- её **прогресс приходит с сервера** и считается по страницам, а не по тику
  таймера.

Порядок замены имитации настоящим описан в
[AI-BACKEND.md](./AI-BACKEND.md), раздел «Как добавить новую операцию».

### Проверки живут в одном месте и работают дважды

`lib/auth/validation.ts` и `lib/validation.ts` используются и браузером — чтобы
подсветить ошибку до отправки, — и серверным действием, чтобы отказать
запросу мимо интерфейса. Серверное зеркало проверки реквизитов живёт в базе
(`app.validate_entity`) и пересчитывается триггером: клиент физически не может
объявить объект валидным.

### Никаких вызовов модели из приложения

Даже быстрых. Подробности и порядок добавления операций — в
[AI-BACKEND.md](./AI-BACKEND.md).

## 4. Частые задачи

### Добавить поле в дело

1. Миграция в `supabase/migrations/` — колонка.
2. `npm run db:types` — перегенерировать типы базы.
3. `lib/data/mappers.ts` — перевод строки в тип фронта.
4. `types/index.ts` — поле в тип интерфейса.
5. Действие в `app/actions/cases.ts` — разрешить запись.

### Добавить страницу приложения

Создать `app/<путь>/page.tsx`. Если страница читает данные пользователя —
обязательно `export const dynamic = "force-dynamic"`: без этого сборка без
переменных окружения зафиксирует её статической, и на боевом сервере она
отдаст встроенный набор вместо настоящих дел.

Защита от неавторизованных делается сама — в `middleware.ts` перечислены
публичные пути, всё остальное закрыто.

### Добавить форму настроек

Компонент в `components/settings/`, действие в `app/actions/workspace.ts`,
раздел на странице через `SettingsSection` с якорем — он попадёт в оглавление
слева.

### Изменить схему базы

Только миграцией. Правка через веб-панель не попадёт в репозиторий, и при
переезде на self-hosted её никто не воспроизведёт. Новое изменение — новый
файл в `supabase/migrations/` с временной меткой в имени.

## 5. Проверка перед коммитом

```bash
npm run typecheck && npm run lint && npm run build
```

Все три обязаны пройти. Сборка ловит то, чего не видит проверка типов:
серверный код, случайно попавший в клиентский бандл, и страницы, которые
падают при отрисовке.

Тестов в проекте пока нет. Это осознанный пробел, а не забывчивость: продукт
менялся быстрее, чем успевали устаревать тесты. Первое, что стоит покрыть,
когда форма стабилизируется, — `lib/validation.ts` и `lib/ai/jobs.ts`.

## 6. Выкладка

**Приложение** — Netlify, сборка из `main`. Переменные окружения задаются в
Site configuration → Environment variables. `SUPABASE_SERVICE_ROLE_KEY` нужен
только для отправки писем-приглашений; без него приложение работает.

**Схема базы** — `npm run db:push` с машины разработчика или через панель
Supabase.

### Исполнитель заданий

Это Edge Function `ai-worker` — отдельная программа на стороне Supabase,
единственная во всём проекте, кто имеет право звонить модели.

Зачем он нужен вместо прямого вызова из приложения. Запрос к Netlify живёт
десять секунд, а распознавание одной страницы у qwen3-vl занимает около
пятидесяти пяти — приложение не дождалось бы даже первой. Поэтому приложение
только кладёт строку в `ai_jobs` и сразу отвечает, а всю долгую работу делает
исполнитель.

Работает он так:

```
приложение → строка в ai_jobs → [ждёт] → исполнитель забирает → модель
                                              │
                    pg_cron раз в минуту ─────┤
                    толчок после постановки ──┘
```

Забирает задание `claim_job` с `for update skip locked`: два исполнителя,
запущенных одновременно, не возьмут одну работу дважды — а это прямые деньги.
Не успел за отведённое время — возвращает задание в очередь и продолжит в
следующий заход, поэтому восемнадцатистраничный скан проходит несколькими
запусками, а не падает по тайм-ауту.

Выкладка — `supabase functions deploy ai-worker` плюс секреты:

```bash
supabase secrets set LLM_API_KEY=... LLM_BASE_URL=... LLM_MODEL_VISION=...
```

Ключ к модели в переменные Netlify не кладите: приложение не должно уметь
позвать модель напрямую даже теоретически.

**Проверить модель до выкладки:**

```bash
npm run check:vision -- --list                       # что есть в каталоге
npm run check:vision -- скан.pdf --model <имя>       # распознать одну страницу
```

Скрипт проходит ровно тот путь, которым пойдёт распознавание в Edge Function:
тот же движок, тот же кодировщик, тот же запрос. Поэтому по его выводу видно,
где сломалось — на рендере, на формате картинки или на самой модели. Ключ он
берёт из `.env.local`, в аргументах передавать не надо.

**Ключ для приложения заводите с лимитом.** У маршрутизатора есть мастер-ключ,
которым создаются обычные ключи, и у каждого можно задать потолок расхода:

```bash
curl https://routerai.ru/api/v1/keys --request POST \
  --header 'Authorization: Bearer <мастер-ключ>' \
  --header 'Content-Type: application/json' \
  --data '{"name":"aleteya-ocr","limit":1000}'
```

Мастер-ключ в приложение не кладут никогда: он умеет создавать и удалять
ключи, а не только тратить деньги. В секреты функции уходит обычный ключ с
лимитом — тогда ошибка в цикле обойдётся в потолок, а не в весь баланс.

Каталоги `scripts` и `supabase/functions` намеренно исключены из `tsconfig`:
первое — инструменты разработчика, второе — код Edge Function с собственным
окружением. Проверять их общей проверкой типов приложения нечем.

Необязательные секреты исполнителя:

| Секрет | По умолчанию | Зачем |
|---|---|---|
| `OCR_CONCURRENCY` | `10` | Сколько страниц уходит в модель одновременно |
| `OCR_PAGES_PER_RUN` | `12` | Потолок по процессору: рисование его тратит |
| `WORKER_RUN_MS` | `130000` | Момент, после которого исполнителя гасят |
| `PDFIUM_WASM_URL` | jsdelivr | Откуда брать движок PDF, если CDN недоступен |

Движок PDF — файл на четыре с половиной мегабайта, который скачивается при
первом обращении и живёт в памяти процесса. Если внешние адреса закрыты,
положите `pdfium.wasm` в своё хранилище и укажите путь через `PDFIUM_WASM_URL`.

**Расписание.** Без него очередь разберётся только от толчка приложения, а
задание, вернувшееся в очередь после перерыва, повиснет. В SQL-редакторе
Supabase один раз:

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule(
  'ai-worker',
  '* * * * *',
  $$ select net.http_post(
       url := 'https://<проект>.supabase.co/functions/v1/ai-worker',
       headers := '{"Authorization": "Bearer <служебный ключ>"}'::jsonb
     ) $$
);
```

Проверить, что расписание живо: `select * from cron.job;`, а последние запуски
— `select * from cron.job_run_details order by start_time desc limit 10;`.
